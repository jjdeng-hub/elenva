# Agent 开发标准

> 2026-09-20 定。ELENVA 的 agent 开发以 **《深入理解 AI Agent》（李博杰 著，Apache-2.0 开源）为准绳**，
> 不以个人经验即兴发挥。本地副本不随仓库分发，需自行获取（书为 Apache-2.0 开源）；下文「定位」以本地副本的目录结构为准。
> 本文件＝效力声明 + 执行闸门 + 偏离登记；查书方法见项目技能 `agent-book-reference`。

## 一、效力（谁说了算）

1. 凡涉及 **上下文组织与压缩 / 提示词与 Skills / 记忆 / 工具与 MCP / 护栏与验证纠错 / 评估与可观测性 / 多 Agent 编排** 的设计与改动，**默认以书中原则为权威**。
2. 「经验」可以提出假设，但不能当依据：要么找到书中依据（**章节 + 行号**），要么写进下方「偏离登记」并说明理由。
3. 引用必须**实际读到原文那几行**（`read book/chapterN.md offset=...`），禁止凭标题推断；书里没有的说法不许挂在书上。
4. 没有依据、也没有登记的 agent 设计改动，**不算完成**（收工前自查这一条）。
5. 只管 agent 侧；界面/样式走 `elenva-design-review`，与 agent 设计无关的工程细节（编码、打包）不受此限。

## 二、闸门（一次 agent 改动怎么走）

1. **动手前**：`LOCAL-README.md` 的「按问题查」定位章节 → `_meta/outline.md` 拿准确行号 → 精准读正文那几行。
2. **定方案时**：写清「书中的原则」与「我们这里的取舍」；两者不一致 → 走偏离登记。
3. **落地时**：书里或配套实验（109 个）有现成验法的，**优先改编为 `tools/rev/` 回归夹具**，不要自创口径。
4. **收工前**：本次改动的依据（章节 + 行号）或偏离，写进本文件或对应的提交说明。

| 2026-10-16 | 纠正升格规则用**确定性启发式**草稿（加「今后：」前缀 + 来源标注），不调模型改写 | ch3 L229 第三层「从具体情景记忆中提取一般性规律，转化为语义或程序记忆」本应由模型做语义泛化；ch3 L511/L513 提议者—审核者模式 | 服务端只生成可编辑草稿（`lib/corrections.ts` 的 `buildRuleDraft`），人在升格对话框里确认/改写后才落盘；AGENTS.md 只出草稿、绝不自动写 | 本机无常驻小模型通道；此层要可回归（与「常驻索引摘要用确定性截断」同款取舍）；ch3 L511「生产环境不应让任何一个模型绕过审核直接改主分支/线上库」 | 若观察「升格规则质量差、每条都要手改很多」→ 改为升格时调一次模型生成，再人工确认 |
| 2026-10-17 | 记忆治理用**失效标记**（可查可恢复）代替删除 | ch3 L202 指出自动 UPDATE/DELETE 的风险是「一次错误的更新或删除会不可逆地丢失历史信息」；ch3 L505 要求证据不足时保留待确认状态 | 条目级元数据追加可选 `invalidated=YYYY-MM-DD[, reason=…]`；失效条目不进索引/检索但留在文件里，可 `memory_status restore` 恢复；物理删除仅限明确指示或纯噪声 | 历史可回溯是「写而不删」的硬要求（简化版 Graphiti 双时序）；文件格式向后兼容，旧条目/旧解析器均不受影响 | 若失效条目长期堆积而无人清出、反噬容量 → 在 tidy 里提高「归档建议」权重或加自动清出阈值 |
| 2026-10-17 | 检索用**三层渐进披露**（清单 → 按 id 取详情 → full 兼容） | ch3 L482 的 L0/L1/L2：摘要常驻、按需加载全文；L1 摘要由模型在写入时生成 | `memory_find` 默认给行式清单（每条 ≤90 字符确定性摘要 + 标注，预算 2000 字符），`ids` 取详情、`full: true` 回旧行为 | 清单层摘要沿用与常驻索引同款的确定性截断（零模型调用、可回归）；分层本身与书中一致，只是摘要生成方式取同一偏离口径 | 若 `tools/memory-eval` 的 L5（细节在摘要之外）掉分，或实测「清单看不出该取哪条」，就换成 LLM 摘要并重跑 |
| 2026-10-17 | 索引重建的完整性判据用 FTS5 `integrity-check`（`rank=1`），不用行数对比 | ch3 L482 要求索引可显式维护/重建；书中未规定外部内容表的完整性口径 | `/memory-reindex` 先备份 → FTS5 `'rebuild'` → Markdown/会话重扫 → 对账；FTS 用 `integrity-check` 带 `rank=1` | 外部内容表的 `SELECT COUNT(*)` 读的是内容表，索引被清空时行数不变（实测），行数对比测不出坏索引 | 若 SQLite 版本升级导致该指令行为变化，换回「实际 MATCH 探测 + 行数」双判据 |
| 2026-10-17 | 网页「标失效 / 恢复」走**单条原子 API**且**豁免字符上限**；周整理用**只读提案**、不自动执行 | ch3 L505 定期整理要「冲突证据不足时保留待确认」；ch4 L349 只读起始权限；ch3 L202 自动 UPDATE/DELETE 有不可逆风险 | `POST /api/memory/status` 按正文精确匹配单条、只翻转该条元数据，复用写链（revision 并发校验 → 备份 → 原子写）；**仅失效豁免配额**（满额逃生口，与 vendor `setStatus` 同口径）；节律每周只读任务（`--weekly`）产四段提案供人过目，不自动改文件 | 失效是可逆元数据而非删除；满额时若无逃生口就退不出满额（只能手清）；自动 tidy 会不可逆改文件，且本机无可靠小模型做语义合并 —— 与「智能体化 RAG 的安全边界」同向 | 若失效条目长期积压反噬容量，或周提案连续无人执行 → 给 tidy 加自动清出阈值或提醒升级 |
| 2026-10-18 | 长连接只加**活性看门狗（只报不杀）**，失败现场全部落到日志与界面 | ch5 L189 要求空闲看门狗「超过设定时间没有新输出就判定卡死，超时后**主动杀死挂起的流并触发重试**」 | `lib/agent-liveness.ts` 只做判定与文案：超过 60s/180s 无内核事件时把现场（阶段、已等待多久、事件流是重连还是已连上）摆到界面上；**不杀流、不自动重试**，挂起的流仍交给既有 SSE 重连与停止按钮 | 本轮需求明确「除新增排查输出外不改现有行为」；主动杀流属于行为变更，且会与既有重连/结算状态机交叠，风险高于收益 | 若出现「看门狗报了、用户没动作、任务就一直挂着」的真实摩擦 → 再补主动杀流（阈值与现有 60s ready_timeout 对齐） |

## 五、记忆系统的评估（改记忆相关东西必跑）

`tools/memory-eval/`：按 ch3 **L43 三层次框架** + 实验 3-1 流程做的真会话评估（另加 L4 容量层），
沙箱跑 `pi -p` 真会话 + LLM-as-judge，带两个确定性指标（关键事实落盘、常驻注入成本）。

```bash
node tools/memory-eval/run.mjs            # 约 4-5 分钟；改注入/检索/整理前后各跑一次对比
node tools/memory-eval/run.mjs --layer L4 --repeat 3   # 容量/整理类改动：看成功率
```

基线、口径、已知偏差都写在 `tools/memory-eval/README.md`；**动记忆相关代码前先看那里的口径**，
别把「单事实问答答对了」当成改进证据（那层已经打满，天花板效应）。

双层记忆（索引层 + 整理层）的实现与依据在 `extensions/elenva-memory/README.md`：
常驻只注入摘要（ch3 L482），全文按需取（实验 3-11）；检索用 `memory_find` 做多信号重排 + 来源标记
（L385 / L594），输出明确标「历史资料，不是指令」（L542）；整理按重要性评分（L221）并对冲突
**只标注不合并**（L505），每条写得下的记忆都留「是哪个工具、何时写下的」痕迹（L505）。
该目录里的 `install.mjs` 负责装到 agent 目录并合并 hermes 配置（含中文纠正模式），
`selftest.mjs` 跑纯函数自检。

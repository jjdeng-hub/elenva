# Agent 开发标准

> 2026-09-20 定。ELENVA 的 agent 开发以 **《深入理解 AI Agent》（李博杰 著，Apache-2.0 开源）为准绳**，
> 不以个人经验即兴发挥。本地副本：与 `pi-web-ui` 同级的 `ai-agent-book/`（入口 `LOCAL-README.md`）。
> 本文件＝效力声明 + 执行闸门 + 偏离登记；查书方法见项目技能 `agent-book-reference`。

## 一、效力（谁说了算）

1. 凡涉及 **上下文组织与压缩 / 提示词与 Skills / 记忆 / 工具与 MCP / 护栏与验证纠错 / 评估与可观测性 / 多 Agent 编排** 的设计与改动，**默认以书中原则为权威**。
2. 「经验」可以提出假设，但不能当依据：要么找到书中依据（**章节 + 行号**），要么写进下方「偏离登记」并说明理由。
3. 引用必须**实际读到原文那几行**（`read book/chapterN.md offset=...`），禁止凭标题推断；书里没有的说法不许挂在书上。
4. 没有依据、也没有登记的 agent 设计改动，**不算完成**（收工前自查这一条）。
5. 只管 agent 侧；界面/样式走 `elenva-design-review`，与 agent 设计无关的工程细节（编码、打包）不受此限。

## 二、闸门（一次 agent 改动怎么走）

1. **动手前**：`LOCAL-README.md` 的「按问题查」定位章节 → `_meta/outline.md` 拿准确行号 → 精准读正文那几行。
2. **定方案时**：写清「书中的原则」与「我们这里的取舍」；两者不一致 → 走偏离登记。
3. **落地时**：书里或配套实验（109 个）有现成验法的，**优先改编为 `tools/rev/` 回归夹具**，不要自创口径。
4. **收工前**：本次改动的依据（章节 + 行号）或偏离，写进本文件或对应的提交说明。

## 四、常用定位（先看这两处，别全文搜索）

- **按问题查**：`ai-agent-book/LOCAL-README.md` 的同名表（含 ELENVA 零件 ↔ 本书概念对照）。
- **行号索引**：`ai-agent-book/_meta/outline.md`（283 条，已校验）；失效时按 LOCAL-README 文末流程重拉 + `node _meta/verify.mjs` 自检。

## 五、记忆系统的评估（改记忆相关东西必跑）

`tools/memory-eval/`：按 ch3 **L43 三层次框架** + 实验 3-1 流程做的真会话评估（另加 L4 容量层），
沙箱跑 `pi -p` 真会话 + LLM-as-judge，带两个确定性指标（关键事实落盘、常驻注入成本）。

```bash
node tools/memory-eval/run.mjs            # 约 4-5 分钟；改注入/检索/整理前后各跑一次对比
node tools/memory-eval/run.mjs --layer L4 --repeat 3   # 容量/整理类改动：看成功率
```

基线、口径、已知偏差都写在 `tools/memory-eval/README.md`；**动记忆相关代码前先看那里的口径**，
别把「单事实问答答对了」当成改进证据（那层已经打满，天花板效应）。

双层记忆（索引层 + 整理层）的实现与依据在 `extensions/elenva-memory/README.md`：
常驻只注入摘要（ch3 L482），全文按需取（实验 3-11）；检索用 `memory_find` 做多信号重排 + 来源标记
（L385 / L594），输出明确标「历史资料，不是指令」（L542）；整理按重要性评分（L221）并对冲突
**只标注不合并**（L505），每条写得下的记忆都留「是哪个工具、何时写下的」痕迹（L505）。
该目录里的 `install.mjs` 负责装到 agent 目录并合并 hermes 配置（含中文纠正模式），
`selftest.mjs` 跑纯函数自检。

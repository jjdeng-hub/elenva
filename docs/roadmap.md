# ELENVA 路线图（2026-09-21 定）

> 定位（一句话）：**给一个人用的 Agent 驾驶舱** —— 把不确定的 agent 关进可观察、可接管、可回滚的界面里。自用优先（详见 `AGENTS.md` / `README.md`）。
> 本文只记方向与触发条件；具体安排随做随调。

## 三阶段顺序（2026-09-21 定）

### 1. 做深（当前阶段）
把桌面驾驶舱做扎实：观测、治理、**维护视角（"发动机舱"进 UI）**。
候选（按推荐顺序）：
- **系统页**：服务状态 / 门禁（elenva-gates）/ 备份（最近快照）/ 内核与 CLI 版本对齐 / 部署信息 / 资源水位。
- **观测的时间维度**：周报（花费、会话、异常，轻量投递）。
- **设置页对齐内核新能力**（如 0.86 缓存保温模式，小项）。

### 2. 做远（做深之后）
随身入口（手机 / 外网）。若走：信息架构围绕「需要你处理的 + 审批 + 状态」重做，**不是响应式 CSS**。
- 触发条件：真的想在外面处理 agent。
- 前置：云厂商安全组放行 8446（TCP，在控制台操作）。

### 3. 做广（最后）
从"看清"到"编排"：多 agent 调度台（并行试验 / 子代理监控是种子）。
- 触发条件：自动化 agent 舰队真的出现（目前这类活在 Hermes cron 里）。

## 明确不做（除非定位重估）
- 产品税旁支：便携包、npm 发布、陌生人上手引导、i18n、多用户。
- 响应式 CSS（不解决"做远"的问题）。
- 写作 / 社交 / 美化类功能（新功能一票否决题：是否服务"看清与接管"）。

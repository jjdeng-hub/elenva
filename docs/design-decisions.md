# 设计决定登记

记录那些「看起来像 AI 默认、其实是本项目有意选择」的做法。UI 审计的自动扫描器
（avoid-ai-design detect v0.4.0）会把这些报成命中项；此处逐条说明理由，避免以后被当成
问题顺手改掉。**经 UI 审计（2026-10-17）确认保留。**

## 1. 红黑白身份 & 深色「近黑 + 朱红」（扫描器 SD2）

浅色是暖白纸感 + 墨黑正文 + 单一朱红（`#c9302c`）作动作与选中色；深色把地面压到
`#161614` 的近黑，红色整体提亮为 `#e87b78`。

SD2 说「近黑 + 单一朱红」是第二个「有品味」默认簇 —— 对陌生项目成立，但这里的红是
**品牌红**：它同时承担动作、警示、选中三类语义（见 `globals.css` 里 accent/danger 同源
与 viz 色阶的注释），不是为了「高级感」临时挑出来的信号色。深色模式只重映射 CSS 变量、
组件层零改动，是本项目最深的一条约定。

## 2. 中间点「·」分隔同类信息（扫描器 SD4d）

元信息里用「 · 」把同类值连成一行（如「105.41M · $5.13」「运行中 2 · 等你处理 1」），
是本项目的**信息密度**选择：这些值同源、同粒度、需要一眼横向比较，拆成多行会让卡片长高、
扫读变慢。SD4d 针对的是「装饰性」的模板化元信息行；这里每个点连接的都是有意义的字段，
不是填充节奏。用量分析「按项目」一行同时给出占比 / token / 成本即属此类。

## 3. 等宽小字用于数据与度量（扫描器 SD4m）

模型名、命令、路径、hash、token 与成本读数用 `var(--font-mono)` + 11/12px —— mono 让
数字逐位对齐，是本工作台的核心内容类型（它首先是给自己读运行数据的工具，不是营销页）。
SD4m 针对的是「用 mono 装小标签凑科技感」；这里的 mono 只包**真数据**，纯标签一律走
`.label-micro`（11px / 500），不用 mono。

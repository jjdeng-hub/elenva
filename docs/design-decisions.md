# 设计决定登记

记录那些「看起来像 AI 默认、其实是本项目有意选择」的做法。UI 审计的自动扫描器
（avoid-ai-design detect v0.4.0）会把这些报成命中项；此处逐条说明理由，避免以后被当成
问题顺手改掉。**经 UI 审计（2026-10-17）确认保留。**

## 1. 红黑白身份 & 深色「近黑 + 朱红」（扫描器 SD2）

浅色是暖白纸感 + 墨黑正文 + 单一朱红（`#c9302c`）作动作与选中色；深色把地面压到
`#161614` 的近黑，红色整体提亮为 `#e87b78`。

SD2 说「近黑 + 单一朱红」是第二个「有品味」默认簇 —— 对陌生项目成立，但这里的红是
**品牌红**：它同时承担动作、警示、选中三类语义（见 `globals.css` 里 accent/danger 同源
与 viz 色阶的注释），不是为了「高级感」临时挑出来的信号色。深色模式只重映射 CSS 变量、
组件层零改动，是本项目最深的一条约定。

## 2. 中间点「·」分隔同类信息（扫描器 SD4d）

元信息里用「 · 」把同类值连成一行（如「105.41M · $5.13」「运行中 2 · 等你处理 1」），
是本项目的**信息密度**选择：这些值同源、同粒度、需要一眼横向比较，拆成多行会让卡片长高、
扫读变慢。SD4d 针对的是「装饰性」的模板化元信息行；这里每个点连接的都是有意义的字段，
不是填充节奏。用量分析「按项目」一行同时给出占比 / token / 成本即属此类。

## 3. 等宽小字用于数据与度量（扫描器 SD4m）

模型名、命令、路径、hash、token 与成本读数用 `var(--font-mono)` + 11/12px —— mono 让
数字逐位对齐，是本工作台的核心内容类型（它首先是给自己读运行数据的工具，不是营销页）。
SD4m 针对的是「用 mono 装小标签凑科技感」；这里的 mono 只包**真数据**，纯标签一律走
`.label-micro`（11px / 500），不用 mono。

## 4. Agent 工作台与首页共用同一套「门牌」母题

应用包 Agent（内容 / 装修 / 生活助手……）的工作台头部复用首页的「时钟 + 问候」：等宽时刻 +
`M月D日 / 星期X` + `早上好 · <Agent 名>`。理由：这是一个小区里的不同户型——进门第一眼
（几点、今天、跟谁在说话）应该一致，Agent 之间只该差在**房间里放什么**，不该差在门牌长什么样。
`greeting()` / `clockLabel()` / `dateLines()` 收在 `lib/format.ts`，首页与工作台同源，别各写一份。

同一逻辑下，`cards` 块渲染成统计砖而不是列表行：第一格跨两列并带 accent 底（它是「现在最重要
的那个数」），其余保持一格；值 ≤12 字走 18px 大字，长句自动降到 13px 并允许两行——四块等宽
等于没有主次，读的人不知道先看哪个。时间线用左侧日期列 + 竖轨 + 圆点，最后一条红点，今年
的条目省掉年份（`2026-11-11` → `11-11`），一列日期里混年份会把眼睛拽走。

## 5. 一个视图一条链接

`#a/<agentId>/<viewId>` 由 `AgentWorkspace` 自己读写（`replaceState`，视图切换不进浏览器历史），
平台层 `AppShell` 只负责「别把它改写掉」——`home` 视图必须保留地址栏里的视图段，否则深链接
会在子组件挂载前被抹成 `/home`。这不是路由框架，只是让「我在跟谁说话、在哪个房间」写进地址栏。

## 6. Agent 工作台的视图切换 = 顶部标签条（不占一列）

应用包的视图（今天 / 练 / 日志、选题库 / 草稿台…）用**文字标签 + 2px 下划线**放在内容区顶部，
与右栏面板标签同一套语言；不再用一条 216px 的左侧栏。理由：那条栏只装得下三个词，却永久吃掉
内容宽度的四分之一——表格和统计砖在 667px 里挤成一团，移到顶部后同一屏宽到 883px。
角标只给「有下一步动作」的视图（队列数「等你」的、正文数篇数），不再把各块条目数相加——
「今天 9」这种数字读的人无从解释。数字键 1..9 可切视图（输入框内不抢键）。

## 7. 空状态与加载态是应用包的话，不是平台的话

块的空状态用 manifest 的 `emptyHint`（≤160 字）由应用包自己写：「练完报一句，我按日期补一行」
比「暂无数据」多告诉人一件事——下一步该做什么。平台只留位置，没写时才退回中性文案。
加载态给与真实块同形的骨架（卡头 + 两行），比一行「加载中…」少一次布局跳动。

## 8. 对话只在「会话」页；工作台不放第二份聊天

工作台是看与改的地方（今天 / 练 / 日志、数据块与动作），对话归「会话」页。原来工作台右栏常驻
一个 336px 的聊天面板，等于同一个人开了两扇窗：内容宽度被吃掉四分之一，而且「刚才那句话在哪儿说的」
变成一道选择题。现在工作台头部的「会话」按钮把人送过去；块上的动作（「就这条聊」「复盘这次」）
发出 prompt 后也自动切到会话页——话已经发出去了，人应该看得见它跑。

会话页同时是「同一个我、多个入口」的证据：列表按飞书 / 定时 / 工作台 / 终端标注来源，
点开哪条就续哪条（`session/load`），刷新页面不丢。

## 9. Agent 级六个页面 = 同一个 profile 目录的六种投影

对 Hermes 运行时的应用包，「会话 / 记忆 / 技能 / 节律 / 成长 / 身份」不是六套实现，而是
`lib/agents/resources.ts` 读同一个 profile 目录（默认 profile 在 `~/.hermes/`，其余在
`~/.hermes/profiles/<id>/`）后的六个视图，统一走 `GET /api/agents/resources?kind=…`。
代码 / 提示词两个视图对这类 Agent **设计上不适用**（不是待办）：代码视图留给编码 Agent；
提示词不是一份文件，而是 SOUL + 记忆索引 + 技能索引在会话启动时拼成的——页面直接说清去哪改，
不要写成「接入中」。

## 10. 会话页不是「消息 + 输入框」，是一条可监督的执行链

一个 Agent 的价值大部分发生在会话里，所以这里必须回答三个问题：**它在干什么、要不要放行、这轮花了多少**。
只做「气泡 + 输入框」等于把人关在门外等——五分钟的沉默和「它坏了」长得一模一样。

- **过程**：每次工具调用一张卡（状态点 / kind / 标题 / 路径 / 耗时 / 输出或 diff），插在
  「用户那句话」之后、「最终回答」之前；正在跑与失败的默认展开，成功的自动收起。
- **拍板**：授权卡带上下文（改哪个文件、old → new 的 diff），选项分主次，
  并明说「不选的话，这一轮就停在这里」。
- **收尾**：每轮一行账（步数 / 用时 / ↑↓ token），失败给原因和「重试上一条」。
- **不丢**：刷新或断线回来，本轮的用户那句话、已有的过程卡、还挂着的审批都要能补回来
  （宿主保留本轮事件日志 + `/pending` 带 `toolCall`），不能只剩一个空输入框。

## 11. 会话是一条能断、能续、能看懂的线程

- **边界要说出来**：`data/chat.jsonl` 是一个应用包的滚动对话记录，但 ACP 会话有多次生死。
  新建会话时落一行 `{role:"session"}`，界面上画一条「新的会话从此开始，上面的它不记得」——
  否则刷新后上下文其实是新的，人却以为它还记着，怪它「失忆」。
- **草稿是会话的一部分**：没发出去的话按 Agent 存本地，切走、刷新都还在；发送后才清。
- **断线不是错误**：SSE 断开只亮「正在重连」，连上自动消失。宿主不可用时**必须回 200 +
  `text/event-stream`**（哪怕只发一条 `host_down`）——EventSource 收到 JSON 会永久关闭，再也不重连。
- **输入法优先**：`isComposing` 期间的 Enter 是选词，不是发送；运行中 Esc 停止。
- **重置是破坏性操作**：两步确认（「重置会话」→「确认重置？」4 秒后自动回到第一步），
  它同时清掉 `data/chat.jsonl` 与 Agent 上下文。

## 12. 模型是会话的属性，不是平台的属性

会话头部的模型下拉值来自 ACP `session/new` 返回的 `models`（`availableModels` + `currentModelId`），
切换走 `session/set_model`——只影响这一条会话，**不改 profile 的 config.yaml**：
飞书、终端、定时任务里那个自己仍按 profile 配的模型跑。

- 模型清单只存在于活着的会话里，所以打开会话页会用 `GET /models?start=1` 顺手把 ACP 会话建起来；
  建会话不等于发话，`data/chat.jsonl` 里不会因此多出任何一行（边界行延到第一句话前才写）。
- 一轮正在跑时禁用切换（按钮置灰并说明原因），避免「这一句到底谁答的」说不清。
- 下拉里按 `provider:model` 拆分显示：左边模型名、右边 provider 小标签，搜索同时匹配 id / 名称 / 描述，
  打开时把当前项滚到中间（50+ 个模型里找自己那个很烦）。

## 13. Hermes 会话 = ELENVA 会话（不另造一套界面）

第一版给 Hermes 单独写了一套会话界面，结果同一个平台里两种对话长得不一样，
切 Agent 要重新认界面。**这是错的**：会话是平台的能力，不是运行时的能力。

现在的做法：`components/HermesChat.tsx` 只做一件事——把 ACP 的 `session/update` 流翻译成
`lib/types.ts` 的 `AgentMessage`（`lib/acp-chat.ts`），然后交给平台自己的
`ChatWindow`（消息 + 工具卡 + diff + 思考块）、`ChatInput`（输入框 + 附件 + 草稿 + 模型槽）、
`ModelPicker`（模型清单）渲染。换 Agent 不换界面。

- 工具名归一：`write_file → write`、`patch → edit`、`terminal → bash`，MessageView 的
  图标与 diff 渲染才认得出；审批里拿到的 old/new 转成 Pi 的 `±` 行格式塞进 `details.diff`。
- 审批卡不在 `ChatInput` 里（它只渲染 `extensionBelow`），挂在输入区上方；
  并且**每 3 秒对一次 `/pending`**——SSE 事件丢了不能让整轮静默卡死。
- 附件暂时只记数量：ACP 的 prompt 只收文本，图片上传要另做端点。

## 14. 单一真源与投影式 UI（2026-11-12）

**数据由运行时/Agent 生产，UI 只做投影。**原来会话有两处真源：Hermes 的 `state.db` 已有完整记录
（含工具调用、标题），ELENVA 又在应用包写了一份 `data/chat.jsonl`，靠同步维持一致——实测已经不一致
（刷新后工具输出和标题都丢）。结论：删除 `chat.jsonl`，不再写、不再读、不做迁移（历史在 state.db 里）。

- **会话识别口径是 `cwd`，不是 `source`**：ACP 探针建的空会话是 `source='acp'`、`message_count=0`；
  真实会话是 `source='local'` + `cwd='<应用包目录>'`。同时忽略 `message_count=0` 的空会话。
  读取集中在 `lib/agents/resources.ts`（state.db 是 Hermes 内部结构，升级 Hermes 只改这一处）。
- **工具调用序列在资源层拼**：assistant 行的 `tool_calls`（JSON 数组）与后续 `role='tool'` 行
  按 `tool_call_id` 配对，产出 `toolCalls[]`（含参数与结果正文）；
  `lib/acp-chat.ts` 的 `hermesDbToMessages` 转成平台的 `AgentMessage`。
- **宿主瘦身**：`bin/acp-host.cjs` 删掉落盘（`historyPath`/`appendHistory`、prompt 收尾写记录、
  `/reset` 清盘）与 `/history` 读盘端点；历史由 `/api/agents/chat/history` 直连资源层读 state.db。
- **不变量**（详见 `docs/specs/2026-11-12-single-source-of-truth.md`）：每类数据只有一个真相来源；
  UI 只读不写；界面动作产出的是意图，交给 Agent 落盘；领域数据（data/*.json）先有
  路径/schema/schemaVersion/写入口径四件事的契约（应用包 `AGENTS.md`），界面才渲染。
